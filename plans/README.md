## Findings considered and rejected

- **`lodash@4.18.1` pin is suspicious**: rejected — 4.18.1 is a real current
  registry release; the finding is the dependency's presence (plan 009), not
  the version.
- **`src/unsplash/` dead code**: rejected — directory already deleted in
  commit `5a550cb`.
- **`prettier` alongside `oxfmt`**: rejected — used only for deterministic
  HTML normalization in `test/utils/e2e.ts`; legitimate.
- **`react-highlight` in demo**: originally flagged low-value; included in
  plan 013 since removal is trivial and the user asked for all findings.
- **Opt-in node/transformer list for the markdown API** (docs open
  question 1): not selected by the user for planning; noted in plan 021/022
  as open.
- **Cross-fetch audit signal**: `pnpm audit --prod` reported no known
  vulnerabilities during the audit.
- **Copy Koenig's TypeScript conversion wholesale**: rejected. Its
  `strict: false`/implicit-`any` surface is weaker than Inkling's. Plans 025,
  026, and 028 derive exact Inkling contracts and use Koenig only as behavioral
  evidence.
- **Restore cut Ghost product cards or the monorepo topology**: rejected by the
  confirmed compatibility/product scope. Paywall, signup, product, email CTA,
  call-to-action, transistor, Unsplash, header v1, and legacy package splits
  remain intentionally absent.
- **Keep feature packages external while advertising root-import optionality**:
  rejected by emitted-bundle evidence. The root barrel statically imports the
  features, so optional peers are not optional at module load. Plan 027 chooses
  compatibility-first bundling; async feature subpaths/chunks are deferred as
  a future architecture project because they would reshape sync exports and
  loading behavior.
- **Make Lexical a peer merely to make `.d.ts` files resolve**: rejected. It is
  currently bundled by design, and a second runtime can violate editor
  identity. Plan 028 first bundles/inlines its public type graph and stops for
  review if that proves impossible.
- **Blindly port Koenig's `stylex` and color dependency**: rejected. Plan 035
  takes the typed email-button behavior but uses Inkling's local color helper
  and a narrow fixed-property serializer.
- **Restore drag sibling-displacement animation immediately**: deferred.
  Koenig applies transforms during drag, while Inkling has a substantially
  rewritten drag/drop stack and an unused transformed-droppable tracking set.
  No correctness regression or accepted motion specification was established;
  porting transforms without visual/reduced-motion QA would add risk. Revisit
  as a standalone UX plan if product owners want the animation.
- **Change `keepWithinSpacing`'s overwritten `origin` argument now**: deferred.
  The code is suspicious, but wide-card compensation is distributed across the
  hook. Plan 033 characterizes coordinates and fixes only the proven cleanup
  leak; geometry changes require a red user-visible case.
- **Treat analytics stubs and `inkling.local` placeholder assets as accidental
  omissions**: rejected/deferred by plan 024's triage. They are integration
  seams, not safe upstream ports, until a host analytics/asset contract exists.
- **Inject bookmark metadata HTML to match richer upstream rendering**:
  rejected. Inkling's renderer intentionally uses text/escaped attributes;
  reintroducing raw metadata would weaken the existing security boundary.
